Official VictoriaLogs Recommendation & Industry Standard
──────────────────────────────────────────────────────────────────────────────────────────────────
Single node or cluster?             Single node for under ~1TB/day; cluster beyond that
How to do tiering?                  Not officially recommended — use -retentionPeriod instead; they handle deletion automatically
Prometheus + VictoriaLogs hybrid?   Not officially recommended — VictoriaLogs is for logs, VictoriaMetrics is for metrics; keep separate
Production load balancing?          Use vmauth in front of vlinsert and vlselect — it is the official LB component
_stream_fields config?              Always configure — critical for even distribution and query performance
Replication?                        Achieve at collection layer (send same logs to multiple vlinsert endpoints), not storage layer
Kubernetes?                         Official Helm chart: victoria-logs-cluster with vmauth, vlinsert StatefulSet, vlselect Deployment
Industry standard (2025)            VictoriaLogs cluster + vmauth + Vector collector — this is the reference architecture
